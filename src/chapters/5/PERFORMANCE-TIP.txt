Performance in Three.js

Quando sviluppiamo scene in Three.js, l’obiettivo è avere almeno 60 FPS costanti, 
ma per utenti con computer potenti (gamers) l’ideale è puntare più in alto, 
così eventuali cali non compromettono l’esperienza. I due principali colli di bottiglia sono la CPU e la GPU, 
quindi è fondamentale testare su dispositivi diversi, anche mobile.

Oltre al frame rate, bisogna tenere d’occhio il peso complessivo del sito, 
perché ciò che in locale carica velocemente può diventare lento online a seconda della connessione.


Monitoraggio
Per misurare le performance conviene usare strumenti reali:
FPS con stats.js:

import Stats from 'stats.js'

const stats = new Stats()
stats.showPanel(0) // 0: fps
document.body.appendChild(stats.dom)

const tick = () => {
    stats.begin()
    // ...rendering e logica
    stats.end()
}


JavaScript e ottimizzazioni generali

Evitare di creare oggetti nel loop di rendering: riciclare Vector3, Matrix4, ecc.
Usare BufferGeometry e versioni predefinite buffer (BoxBufferGeometry invece di BoxGeometry).
Oggetti statici: object.matrixAutoUpdate = false e aggiornare manualmente la matrice solo quando serve.
Funzioni e shader: evitare if inutili, usare clamp, mix, defines quando possibile.


Luci e Ombre

Limitare luci dirette (SpotLight, PointLight, DirectionalLight).
Se possibile, evitare l’aggiunta/rimozione di luci dinamiche: invece light.visible = false o light.intensity = 0.
Ombre: costose, usare solo se indispensabile. Possibili ottimizzazioni da fare sulla shadowmap

Mantenere potenze di 2 (256, 512, 1024…) per mipmaps.
Ridurre la risoluzione al minimo necessario.
Preferire texture .jpg o .basis per la GPU.


Geometrie e Mesh

Riutilizzare geometrie e materiali:

const geometry = new THREE.BoxGeometry(0.5, 0.5, 0.5)
const material = new THREE.MeshNormalMaterial()

for(let i = 0; i < 50; i++){
    const mesh = new THREE.Mesh(geometry, material)
    mesh.position.set(Math.random()*10-5, Math.random()*10-5, Math.random()*10-5)
    scene.add(mesh)
}

Per mesh statiche molto simili, usare mergeGeometries:

import * as BufferGeometryUtils from 'three/examples/jsm/utils/BufferGeometryUtils.js'

const mergedGeometry = BufferGeometryUtils.mergeGeometries(arrayOfGeometries)
const mesh = new THREE.Mesh(mergedGeometry, material)
scene.add(mesh)

Per mesh indipendenti ma identiche, usare InstancedMesh:

const instanced = new THREE.InstancedMesh(geometry, material, 50)
for(let i = 0; i < 50; i++){
    const matrix = new THREE.Matrix4()
    matrix.setPosition(Math.random()*10-5, Math.random()*10-5, Math.random()*10-5)
    instanced.setMatrixAt(i, matrix)
}
instanced.instanceMatrix.setUsage(THREE.DynamicDrawUsage)
scene.add(instanced)


Modelli e compressione

Mantenere low-poly e usare normal maps per dettagli.


Camera e Renderer

Ridurre frustum e near/far per frustum culling efficace.
Limitare pixel ratio su device high-dpi:
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2))


Power preference per render:

const renderer = new THREE.WebGLRenderer({
    canvas: canvas,
    powerPreference: 'high-performance'
})


Post-processing e shader

Limitare il numero di pass in EffectComposer.
Precisione shader: precision: 'lowp' quando possibile.
Calcoli intensivi nel vertex shader, fragment shader solo per colori finali.
Evitare Perlin noise costoso, usare texture di rumore quando possibile.
Uniforms statici → defines.


Suggerimenti finali

Riusare tutto ciò che si può (oggetti, materiali, geometrie).
Evitare trasparenze pesanti, usare alphaTest quando possibile.
Oggetti lontani → LOD, aggiornamenti meno frequenti.
Oggetti statici → matrixAutoUpdate = false.
Post-processing → raggruppare pass quando possibile.


Suggerimenti generali per le performance in Three.js

La creazione di oggetti in JavaScript è costosa, 
quindi evita di generarli dentro i loop. 
Ad esempio, invece di creare un nuovo Vector3 ad ogni frame, 
creane uno e riutilizzalo con vector.set():

const tempVector = new THREE.Vector3();
for (let i = 0; i < 100; i++) {
    tempVector.set(Math.random(), Math.random(), Math.random());
    // usa tempVector per posizionare oggetti...
}
